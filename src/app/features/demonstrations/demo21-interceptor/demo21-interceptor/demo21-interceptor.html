Interceptor

Qu'est-ce qu'un interceptor ?

Un interceptor est une fonction qui s'insère dans la chaîne HTTP : chaque requête sortante et chaque réponse entrante passent par lui. C'est un point de passage unique pour toute la couche HTTP de l'application.

Plutôt que de répéter la même logique dans chaque service (ajouter le token, logger, gérer les erreurs...), on l'écrit une seule fois dans un interceptor — tous les appels HttpClient en profitent automatiquement.

Cas d'usage typiques

  • Authentification : ajouter le header Authorization: Bearer ... sur chaque requête ;
  • Gestion globale des erreurs : rediriger vers le login sur un 401, afficher une notification sur un 500 ;
  • Logging : tracer les requêtes et mesurer leur durée ;
  • Loader global : afficher un indicateur de chargement tant qu'une requête est en cours ;
  • Headers communs : langue, version d'API, etc.

Créer un interceptor

Un interceptor moderne est une simple fonction typée HttpInterceptorFn. Elle reçoit la requête et la fonction next qui poursuit la chaîne :

// logging.interceptor.ts
import { HttpInterceptorFn } from '@angular/common/http';

export const loggingInterceptor: HttpInterceptorFn = (req, next) => {
  console.log('Requête sortante :', req.method, req.url);

  // On laisse la requête continuer son chemin
  return next(req);
};

Comme dans un resolver ou un guard fonctionnel, inject() est utilisable directement dans le corps de la fonction pour accéder aux services.

Enregistrer l'interceptor

On le déclare au niveau du provideHttpClient, dans la configuration de l'application :

// app.config.ts
provideHttpClient(
  withInterceptors([loggingInterceptor])
)

À ne pas confondre avec withInterceptorsFromDi(), qui ne sert qu'à brancher les anciens interceptors écrits sous forme de classes (code legacy d'avant Angular 15).

Modifier la requête : toujours cloner

Les requêtes HTTP sont immuables : on ne modifie jamais req directement, on en crée une copie modifiée avec req.clone(). Exemple classique — ajouter le token JWT :

// auth.interceptor.ts
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = inject(AuthService).token();

  // Pas de token : la requête part telle quelle
  if (!token) {
    return next(req);
  }

  // Copie de la requête avec le header en plus
  const cloned = req.clone({
    setHeaders: { Authorization: `Bearer ${token}` }
  });

  return next(cloned);
};

Intercepter la réponse et les erreurs

next(req) retourne un Observable : on peut donc y brancher des opérateurs RxJS pour observer la réponse ou réagir aux erreurs. Exemple — déconnecter l'utilisateur sur un 401 :

// error.interceptor.ts
export const errorInterceptor: HttpInterceptorFn = (req, next) => {
  const router = inject(Router);

  return next(req).pipe(
    catchError((error: HttpErrorResponse) => {
      if (error.status === 401) {
        router.navigateByUrl('/login');
      }

      // On re-propage l'erreur, sinon le service appelant ne la verra jamais
      return throwError(() => error);
    })
  );
};

L'ordre des interceptors

Plusieurs interceptors forment une chaîne : ils s'exécutent dans l'ordre du tableau pour la requête, puis en ordre inverse pour la réponse :

provideHttpClient(
  withInterceptors([loggingInterceptor, authInterceptor, errorInterceptor])
)
Requête  : composant → logging → auth → error → serveur
Réponse  : serveur → error → auth → logging → composant

Bonnes pratiques

  • Une responsabilité par interceptor : un pour l'auth, un pour les erreurs, un pour le logging — plus lisible et testable qu'un interceptor fourre-tout ;
  • Toujours passer par req.clone() pour modifier une requête — jamais de mutation directe ;
  • Dans un catchError, toujours re-propager avec throwError : une erreur avalée dans l'interceptor devient invisible pour le reste de l'application ;
  • Exclure certaines routes si besoin : un simple test sur req.url permet par exemple de ne pas envoyer le token vers les endpoints publics (/login, /register) ;
  • Les interceptors ne s'appliquent qu'aux appels HttpClient : un fetch() natif passe à côté de toute la chaîne.
