Demo17 : HttpClient

1. Configuration

Pour exécuter des requêtes HTTP, Angular fournit le service HttpClient. Il doit d'abord être enregistré dans les providers de l'application, dans le fichier app.config.ts :

export const appConfig: ApplicationConfig = {
    providers: [
        provideBrowserGlobalErrorListeners(),
        provideRouter(routes),
        // obligatoire pour faire des requêtes HTTP
        provideHttpClient()
    ]
};
2. Le service : émettre la requête

Les appels HTTP se placent dans un service dédié, dans lequel on injecte HttpClient. Chaque méthode (get, post, put, delete...) retourne un Observable : un flux de données auquel on pourra s'abonner. Tant que personne n'est abonné, la requête n'est pas envoyée.

On peut consomer plusieurs services dans un composant , ou même consomer un service dans un autre , il est toutefois préférable de séparer les responsabilités au maximum.

export class DogService {
    private http = inject(HttpClient);

    getDog(): Observable<DogResponse> {
        return this.http.get<DogResponse>('https://dog.ceo/api/breeds/image/random');
    }
}
3. Le composant : consommer la réponse

Pour consommer le contenu de l'Observable, il faut s'y abonner avec subscribe(). On lui passe un objet « observer » avec trois callbacks possibles :

  • next : la requête a réussi — on reçoit les données ;
  • error : la requête a échoué — on reçoit l'erreur ;
  • complete : le flux est terminé sans erreur — aucune donnée n'est transmise. Attention : complete n'est pas exécuté en cas d'erreur (error et complete sont mutuellement exclusifs).
getDog() {
    this.DogService.getDog().subscribe({
        next: (res) => {
            this.imageUrl.set(res.message);
        },
        error: (err) => {
            console.log(err);
        },
        complete: () => {
            console.log('opération terminée');
        }
    });
}

Pour une requête HTTP, le flux émet une seule valeur puis se termine : next puis complete en cas de succès, error seul en cas d'échec.
